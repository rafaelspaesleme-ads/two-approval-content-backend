Documentação de funcionalidades da API

Projeto two-approval-content-backend, baseado em Spring Boot 3.5, Java 21, MongoDB, Spring Security, integração com DeepSeek e envio por e-mail/webhook.

Base path: /api/two-approval-content Swagger: /swagger-ui.html API docs: /v3/api-docs Autenticação: JWT + API keys Banco: MongoDB

Visão geral

Esta API implementa um fluxo de aprovação de conteúdo em duas etapas: primeiro a análise automática por IA e, depois, a avaliação humana. O conteúdo é persistido no banco, a resposta da IA é gravada como referência técnica e o avaliador humano pode consultar e finalizar a decisão.

O contrato de resposta da aplicação usa o wrapper ApiResponse<T>, com os campos responseId, data, title, lsMessage, local, timestamp e metadata.

Fluxo funcional principal

1. Cadastro do avaliador

O avaliador humano se registra com nome, e-mail, nicho e comentários. O sistema cria a evaluationKey e a secretId.

2. Login do avaliador

Com evaluationKey e secretId, o sistema gera um JWT e define a janela de login.

3. Submissão de conteúdo

O criador envia título, conteúdo, e-mail, nicho e, opcionalmente, um webhook de notificação.

4. AI + revisão humana

O conteúdo entra em IN_REVIEW, a IA gera uma avaliação e o humano finaliza o status com justificativa.

End points e responsabilidades

Grupo Método e rota Finalidade Autenticação / cabeçalhos Entrada / saída
Usuários GET
/api/two-approval-content/user/niches		 Lista os nichos disponíveis para cadastro de avaliadores. Sem Bearer. Endpoint público. Entrada: Nenhum body.
Saída: ApiResponse<List<NichesEnum>>
Retorna os nichos cadastrados em enum (ex.: TECHNOLOGY, HEALTH_WELLNESS, TRAVEL, POLITICS, GENERATIVE_AI, etc.).
Usuários POST
/api/two-approval-content/user/register		 Registra um avaliador humano e gera sua chave secreta. Header apiEvaluationKey obrigatório quando não houver Bearer. Entrada: UserRegisterRequest
Saída: ApiResponse<UserRegisterResponse>
Cria o avaliador com secretId gerado internamente e retorna evaluationKey + secretId.
Usuários POST
/api/two-approval-content/user/login		 Autentica o avaliador e emite token JWT. Endpoint público. Entrada: LoginRequest
Saída: ApiResponse<LoginResponse>
Retorna evaluationKey, token, initialLoginAt e expiresLoginAt.
Autor / Conteúdo POST
/api/two-approval-content/author/evaluate		 Envia conteúdo para análise por IA e abre o fluxo de aprovação. Header apiCreatorContentKey obrigatório quando não houver Bearer. Entrada: EvaluateContentRequest
Saída: ApiResponse<EvaluateContentResponse>
Salva o conteúdo com status IN_REVIEW e gera avaliação de IA vinculada ao nicho.
Autor / Conteúdo PATCH
/api/two-approval-content/author/content/{contentId}/find-status		 Marca a visualização do status do conteúdo pelo criador. Header apiCreatorContentKey obrigatório quando não houver Bearer. Entrada: Path variable contentId
Saída: ApiResponse<EvaluateContentResponse>
Atualiza flags internas de leitura do status e, quando aplicável, da justificativa de falha de notificação.
Avaliação humana GET
/api/two-approval-content/evaluation-human/contents/search?evaluationKey={evaluationKey}		 Lista conteúdos pendentes de avaliação humana para o nicho do avaliador. Authorization: Bearer <token>. Entrada: Query param evaluationKey
Saída: ApiResponse<List<InfosEvaluationResponse>>
Retorna conteúdo em revisão junto com a avaliação de IA associada, quando existir.
Avaliação humana POST
/api/two-approval-content/evaluation-human/send-content-evaluation		 Grava a avaliação final feita por um humano. Authorization: Bearer <token>. Entrada: SendEvaluationRequest
Saída: ApiResponse<Void>
Atualiza o status final do conteúdo, grava justificativa e remove a avaliação de IA vinculada ao item.

Regras de negócio identificadas no código

  • O conteúdo entra inicialmente com status IN_REVIEW.
  • O fluxo de AI grava uma resposta em separado, vinculada ao conteúdo e à evaluationKey do nicho.
  • O retorno de status do autor inclui o identificador do conteúdo, o status e a descrição do status.
  • Se existir falha ao enviar notificação, a API também preserva a justificativa da falha para exibição posterior.
  • Na avaliação humana final, a avaliação de IA associada ao conteúdo é removida da base.
  • O endpoint de consulta humana lista apenas conteúdos em revisão e ordenados pela data de criação.

Segurança observada

  • /user/login, /user/niches e a documentação Swagger são públicos.
  • /user/register exige o cabeçalho apiEvaluationKey quando a requisição não vai com Bearer token.
  • /author/** exige o cabeçalho apiCreatorContentKey quando não há Bearer token.
  • /evaluation-human/** depende de autenticação Bearer com JWT.
